# Alforaij Research Assistant — دليل شامل لقراءة المشروع (لأي وكيل/مطوّر جديد)

> هذا الملف هو المرجع الأول لأي وكيل أو مطوّر يفتح المشروع لأول مرة. يشرح المشروع
> كاملًا: ما هو، كيف يعمل، كيف يُشغَّل، بنية كل طبقة، قاعدة البيانات، الاختبارات،
> والنشر — مع تفاصيل عملية تحققت من الكود الفعلي.

---

## 1) ما هو المشروع؟

تطبيق **بحث وتقييم عقاري عربي** لشركة «الفريج» في الكويت، بواجهة ويب وخادم Python
بالمكتبة القياسية فقط (لا FastAPI/Django). يساعد الموظف/الوسيط على:

- فهم طلب العميل من **نص حر** (مثل «بيع بيت في صباح الناصر 400م جديد») عبر `request_parser`.
- البحث في **بيانات الفريج المحلية** + **المصادر الخارجية الحية** (OpenSooq/Mourjan/Q8Aqar/…)
  + **المصادر الرسمية** (صفقات وزارة العدل/الحسبة، المؤشرات الرسمية).
- ترتيب النتائج بدرجة توصية **حتمية (بلا عشوائية)** وتفسير كل رقم: السعر، المساحة،
  الوسيط، نسبة السعر، الثقة، التوصية — مع **أدلة ومصادر قابلة للفتح** لكل حكم.
- توفيق **العرض والطلب**: طلبات «مطلوب للشراء/للإيجار» تُقابل بأفضل الفرص المقيّمة.
- فرص يومية/أسبوعية/شهرية/سنوية، عملاء محتملون، تنبيهات واتساب، موجز أسبوعي،
  وتتبع أداء التسويق (نقرات نسخ/إرسال) في تبويب الأداء.
- الحفظ في **Supabase** عند توفر الاتصال (والعمل بسلاسة كاملة بدونه).

## 2) التشغيل (نقطة البداية الصحيحة)

```bash
cd alforaij-research-assistant
PYTHONIOENCODING=utf-8 python -m backend.main
```

- **لا يوجد `main.py` على المستوى الأعلى** — التشغيل كوحدة من داخل المجلد فقط.
- `PYTHONIOENCODING=utf-8` ضروري على Windows للنص العربي في المخرجات.
- الخادم: `http.server.ThreadingHTTPServer` (مكتبة قياسية) على `127.0.0.1:8000` افتراضيًا.
- تحقق: `curl http://127.0.0.1:8000/api/health` (يعيد `status: ok` + عدّاد الإعلانات + حالة Supabase).

**متغيرات البيئة** (`backend/config.py` يقرأها ويحمّل `.env` إن وُجد):

| المتغير | الوظيفة |
|---|---|
| `ALFORAIJ_ASSISTANT_HOST` / `_PORT` | عنوان/منفذ الخادم (افتراضي 127.0.0.1:8000) |
| `ALFORAIJ_LOG_LEVEL` | DEBUG / INFO / WARNING / ERROR (افتراضي INFO) — سطر واحد لكل مصدر بعد كل تشغيل |
| `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` | قاعدة البيانات (غيابها = تشغيل محلي كامل بتراجع آمن) |
| `AGENT_ROUTER_API_KEY` | تحليل الخبير AI عبر agentrouter (غيابه = تحليل محلي احترافي) |
| `OFFICIAL_TRANSACTIONS_SOURCE` | رابط/مسار CSV/JSON موثق لصفقات وزارة العدل |
| `ALFORAIJ_SEED_LISTINGS` / `ALFORAIJ_BOARD_HTML` | مسار نسخة الفريج / ملف اللوحة |

    official_valuation.py / financing_calculator.py

    ai_evaluator.py        (تحليل الخبير AI أو المحلي)
    opportunities.py       (الفرص: فئات زمنية/توقعات/توفيق العرض والطلب/دلتا/موجز)

    update_notifications.py
  data/              ← seed_listings.json (182) + قواعد/مستخلصات

  migrations/ 001..010   ← مخطط قاعدة البيانات (يُدمج في setup_all.sql)
  setup_all.sql          ← سكربت الإعداد الكامل (تُلحق فيه كل migration)
scripts/               ← أدوات: الحصاد، الاستيراد، التصدير الثابت، فحص الجوال…
tests/                 ← 130 اختبارًا unittest + tests/playwright (فحوص الجوال)
.github/workflows/     ← deploy-static / daily-data-update / mobile-checks / cloudflare

### التدفق الرئيسي (بحث وتقييم)

```
نص المستخدم → request_parser (منطقة/نوع/عملية/مساحة/ميزانية)
           → /api/analyze
           → (اختياري) search_external_sources بالتوازي (ThreadPoolExecutor)
           → top_matches (مطابقة)
           → enrich_rankings (مقارنات + حكم سعر + ثقة)
           → deduplicate_ranked
           → generate_professional_analysis (AI أو محلي)
           → build_report → JSON عربي للواجهة (نتائج/أدلة/مصادر/تمويل/توصيات)
```

**قاعدة مهمة في الواجهة**: النص المكتوب يدويًا في الشات هو **مصدر الحقيقة** — إذا
كتب المستخدم نصًا يخالف قيم حقول الفلاتر القديمة، تُضبط الفلاتر من النص قبل الإرسال
(لا تتغلب القيم القديمة على كلام المستخدم). مسار «بحث وتقييم حسب الاختيارات» من
اللوحة يبني النص من الفلاتر فيتطابقان.

## 5) الموصلات والمصادر — وكيف تُجلب البيانات فعلًا

**الحقيقة التقنية الموثقة**: لا توجد REST APIs عامة لهذه البوابات (تحققنا: `api.4sale.com.kw`
غير متاح، `wp-json` لـ Q8Aqar محجوب). ما نستهلكه هو ما تسمح الصفحة العامة بقراءته:
حمولة JSON مضمّنة (بيانات التطبيق نفسها) أو بيانات منظمة (JSON-LD) أو فحص روابط HTML.
سجل `SOURCE_MECHANISMS` في `live_sources.py` يعلن الآلية لكل مصدر، ويصل لكل حالة مصدر
في التقرير كحقلَي `fetchMethod` + `endpoint` (يظهران في تبويب المصادر سطر «🔎 آلية الجلب»).

| المصدر | الآلية الفعلية | ملاحظات |
|---|---|---|
| الفريج (محلي) | ملف `data/seed_listings.json` (182 إعلانًا) | الخط الأساسي دائمًا |
| OpenSooq | حمولة `__NEXT_DATA__` المضمّنة (بيانات التطبيق) | تُستخرج الكروت والسعر/المساحة |
| OpenSooq (جرد كامل) | مسح صفحات قسمي `property-for-sale` + `property-for-rent` | **كل الأنواع** (شقة/بيت/عمارة/أرض) وكل الصفحات حتى 500 إعلان/حصاد + حماية WAF (إعادة محاولة بانتظار متباعد على 410/429/503)؛ مسار `property/` إلزامي وإلا يعيد الموقع 410 |
| Yebtah | بيانات ItemList منظمة (JSON-LD) من صفحتي البيع والإيجار | يضيف 80 إعلانًا/يوم للحصاد؛ المنطقة/المحافظة تُعرَّب للمطابقة |
| Mourjan | JSON-LD منظم + فحص روابط | مساراته تتغير — يعالجها الموصل |
| Q8Aqar | JSON مضمّن + فحص روابط + **صفحات التفاصيل** للسعر/المساحة | يحسّن القيم بدل الرابط فقط |
| 4Sale | فحص روابط HTML | لا API — يعالج فشل DNS ببديل تلقائي |
| Waseet / Nabdaqar / Aqarat / Bu3qar | فحص روابط HTML وصفحات التفاصيل | سجل تشغيل كامل |
| Sakan | الحالة المضمّنة عند توفرها وإلا فحص روابط | |
| الحسبة العامة | تغذية رسمية من `alhisba.com` (صفقات موثقة) | أعلى مصداقية |
| الصفقات الرسمية | جدول `official_transactions` + ملف محلي + `OFFICIAL_TRANSACTIONS_SOURCE` | تدخل التقييم كوسيط مرجّح أعلى من الإعلانات |
| مؤشرات رسمية | أسعار متر مرجعية (PACI/بنك الائتمان/وزارة العدل) | مرجع لا إعلانات |

**سجل التشغيل**: كل مصدر يُسجَّل (حالة + سبب + مدة + عدد المحاولات) عبر `log_source_run`
مع **منع التكرار الدوري** (نافذة 300 ثانية) حتى لا يتضخم السجل في الفحص الدوري.

**قاعدة المعرفة المتراكمة**: الوكيل اليومي يحصاد كل إعلانات المواقع (`build_opportunities
(return_external=True)`) ويحفظها في جدول `market_listings` مع **`original_url` + `source` +
`fetched_at`** — فتراكم القاعدة مثل بيانات الفريج وتصبح أساس التحليل، لا الفحص الحي فقط.

**وكيل إكمال التفاصيل** (`enrich_listings_from_details` في `live_sources.py`): صفحات القوائم
تعرض ملخصًا فقط، فكثير من الإعلانات يصل بلا سعر أو مساحة أو منطقة أو هاتف. الوكيل يجلب صفحة
تفاصيل كل إعلان ناقص (بالموازاة، بسقف `max_pages` — 40 في الحصاد) ويستخرج الحقول الناقصة
(وسوم وصفية → JSON-LD → نص صريح) ويكمّلها **قبل** فلتر الأسعار والمطابقة والتقييم، ويثبّت
التغيير في `raw["enrichedFromDetails"]` شفافيةً في التقرير. يعمل في مسارَي البحث (`/api/analyze`)
والحصاد اليومي معًا، ويُعلن في تبويب المصادر كحالة «وكيل إكمال التفاصيل».

**هاتف المعلن وزر واتساب**: `_detail_phone` يستخرج رقم تواصل المعلن من صفحة التفاصيل
(روابط `wa.me` → `tel:` → JSON مضمّن في 4Sale → رقم محمول كويتي بسياق اتصال) مع استبعاد
أرقام دعم المواقع (1844474/22260016…)، ويطبّعه إلى `+965xxxxxxxx`. يُحفظ في `market_listings.phone`
(migration 015) ويصل لبطاقات الفرص والنتائج فيظهر زر «تواصل مع المعلن (واتساب)» برسالة
جاهزة تحمل ملخص الفرصة بمصادر أدلتها. ملاحظة: **OpenSooq يخفي الرقم خلف زر كشف** (Firebase +
SSO ملكي — فحصناه)، فالهواتف تأتي من Q8Aqar/Mourjan/4Sale/بوعقار التي تعرضها مباشرة، وترتيب
أولوية القراءة اليومية يوجّه ميزانية الصفحات لهذه المصادر.

## 6) قاعدة البيانات (Supabase) — `supabase/migrations/001..010`

كل الجداول تُنشأ بـ `setup_all.sql` (تُلحق فيه كل migration بأمان). التعامل مع القاعدة
**متسامح تمامًا**: غياب أي جدول أو تعذر الكتابة لا يكسر التشغيل ويُسجَّل السبب.

| الجدول | المحتوى |
|---|---|
| `listings` | إعلانات الفريج المحلية المزامنة |
| `market_ads` | إعلانات السوق الحية (مصدر لوحة العرض) |
| `source_quality` + `source_runs` | جودة المصادر وسجل تشغيلها |
| `opportunities` | لقطات الفرص (فئات/توقعات) عبر الزمن |
| `clients` | العملاء المحتملون (هاتف/منطقة/نوع/ميزانية/ملاحظة) |
| `official_transactions` | صفقات رسمية موثقة (منطقة/نوع/تاريخ/مساحة/سعر) |
| `outreach_clicks` | نقرات التسويق: عميل × إجراء (نسخ/إرسال) × توقيت — عداد لكل عميل |
| `search_history` | سجل البحث |
| `market_listings` | الحصاد الخارجي المتراكم (code فريد + original_url + fetched_at + phone) |
| `market-analytics` (API) | تحليلات الحصاد لكل موقع (عدد/مناطق/وسيط سعر ومساحة) في تبويب المصادر |
| RLS | سياسات service_role + قراءة anon للجداول العامة |

مفاتيح/فهارس رئيسية: `market_listings (code unique, area, source, price, fetched_at)`.

## 7) الواجهة الأمامية (`frontend/` — HTML/CSS/JS بلا build)

### التبويبات الرئيسية (شريط أعلى الموقع — sticky، مع عدّادات حجم المحتوى)

| التبويب | المحتوى |
|---|---|
| 🔍 البحث والتقييم (افتراضي) | الشات + النتائج المرتبة + فرص المكسب + إعلانات المواقع الأخرى + بطاقات المصادر |
| 💎 أفضل الفرص | 12 تبويبًا فرعيًا (أدناه) |
| 📊 لوحة السوق | فلاتر (6 أعمدة) + بطاقات أرقام + جدول المحافظات (صف إجمالي + عدّاد مناطق + توحيد أسماء المحافظات) + إعلانات مرافقة مع «تحليل» + بطاقة ملخص العرض والطلب (زر تنقّل ذكي يفتح تبويب «العرض والطلب» في أفضل الفرص) |
| 📈 تحليلات السوق | خريطة حرارية للمناطق (فجوة السعر/عائد الإيجار + حجز مناطق مراقبة) + KPI + أشرطة عائد بشارات موثوقية (ثقة عالية/تقديري) + محافظات + رسم زمني بمحاور وتلميحات + مصادر التحليل بنِسب |
| 📰 التطورات | وكيل الاكتشاف: أخبار ومؤشرات عقارية كويتية + المنصات المرشحة + حالات مصادر الاكتشاف |
| 🔗 المصادر والتشغيل | الوكيل اليومي + حالة المصادر (بآلية الجلب) + الخطة + منصات الاعتماد + الاستيراد |

### التبويبات الفرعية للفرص (`data-tier`)

`best` (افتراضي — دمج كل الفئات مع شارة الفئة الأدق) · `daily` · `weekly` · `monthly` ·
`yearly` · `forecast` (توقعات الأسعار) · `clients` (العملاء + إضافة عميل) · `alerts`
(تنبيهات واتساب) · `digest` (الموجز الأسبوعي) · `history` (الأداء الزمني — رسم SVG +
أفضل العملاء نشاطًا) · `matching` (العرض والطلب) · `delta` (الجديد والمحذوف بإرشادات).

### أنماط التنقل الذكي

- البحث من لوحة السوق → انتقال تلقائي لتبويب البحث عند اكتمال التحليل.
- **كل رقم في لوحة السوق قابل للنقر** → يفتح درج تفاصيل يعرض الإعلانات الفعلية خلف الرقم
  (بمصدرها ورابطها الأصلي وأدلتها وواتساب)، مع زر «تشغيل نفس الفلاتر في التقييم» أسفل الدرج.
  أسماء المحافظات/المناطق تُوحَّد بالهمزات (الأحمدي/الاحمدي صف واحد) في الخادم والواجهة معًا.
- «بحث مخصص» → يفتح البحث ويركّز على الشات. «المصادر والأدلة» → يفتح المصادر.
- **جوال (≤720px)**: التبويبات شبكة عمودين متساويين (58px)، أهداف لمس ≥44px لكل
  الأزرار/الروابط/الشرائح، صفوف العملاء عمود واحد، جداول تتمرر داخليًا — كل ذلك
  مضمون بفحوص Playwright الآلية (لا ترتد التجاوزات مستقبلًا).

### الوضع الثابت (static) — مهم لفهم «غياب الـ API»

الواجهة تعمل على مضيفات ثابتة بلا Python عبر **لقطة بيانات** (تُصدَّر بـ
`scripts/export_static_frontend_data.py`) وتراجع تلقائي:

- اكتشاف الوضع: `STATIC_SNAPSHOT_MODE = !ALFORAIJ_API_BASE && !isLocalHost` — محليًا
  (127.0.0.1) يعمل بالـ API الحي دائمًا، وعلى مضيف ثابت يعمل باللقطة.
- `POST /api/analyze` يفشل على المضيف الثابت → **تحليل داخل المتصفح** (`staticAnalyzeReport`)
  يحلل نص الاستعلام ويبحث في اللقطة ويعرض الأسباب والأدلة والمقارنات.
- `GET /api/*` يفشل → تراجع تلقائي إلى `static-data/*.json`.
- زر «تنزيل تقرير PDF» في الوضع الثابت يولّد تقريرًا مطبوعًا داخل المتصفح.
- `frontend/config.js` يُحقن بـ `window.ALFORAIJ_API_BASE` عند النشر.

## 8) الوكيل اليومي (`backend/services/daily_update_agent.py`)

خطوات تشغيل واحدة (`POST /api/daily-agent/run` أو `scripts/daily_data_update.py`):

1. `check_official_reference_sources` — فحص المراجع الرسمية.
2. `load_listings` + `save_listings` — مزامنة الفريج.
3. `import_official_transactions` — صفقات رسمية من `OFFICIAL_TRANSACTIONS_SOURCE`.
4. `build_opportunities(include_external=True, return_external=True)` — حصاد كل المواقع
   (مسح عريض: أنواع × معاملات) + بناء الفرص.
5. `save_opportunities` — حفظ اللقطة (أساس مقارنات delta/history).
6. `save_market_listings` — **تراكم إعلانات السوق** في `market_listings`.
7. `discover_market_developments` — وكيل الاكتشاف: يجمع تطورات السوق من مصادر
   كويتية (RSS/HTML بكلمات عقارية + سياق كويتي)، يفحص منصات مرشحة، ويحفظ في
   `market_developments` + `data/market_developments.json` (لا يُفشل الوكيل أبدًا).
8. `build_update_notifications` + `save_update_notifications` — إشعارات التغيير.
9. `send_whatsapp_alerts` — **إرسال تنبيهات واتساب المجدولة** (`backend/services/whatsapp_sender.py`):
   يقارن آخر لقطتين (`build_whatsapp_alerts`) فيرسل رسالة فعلية عبر Meta Cloud API لكل
   عميل مسجل (CSV/Supabase) يطابق فرصة جديدة أو انخفاض سعر. غياب الضبط
   (`WHATSAPP_TOKEN`/`WHATSAPP_PHONE_ID` في `.env`) لا يكسر الوكيل: يُسجَّل
   `not_configured` في الخطوة وتظهر تعليمات الإعداد في تبويب المصادر. سجل محلي
   `data/whatsapp_send_log.json` يمنع تكرار الإرسال لنفس (إعلان × رقم × نوع) في اليوم،
   وكل إرسال يُسجَّل في `outreach_clicks` (action=send, channel=whatsapp_agent)
   ليظهر في عدّادات التفاعل.

الجدولة المقترحة: يوميًا 06:00 (عبر `daily-data-update.yml` — cron 0 3 * * * UTC).

## 9) مبادئ التقييم والثقة (لا عشوائية)

- **درجة التوصية حتمية**: مطابقة الطلب (منطقة 40 + نوع 30 + ميزانية 30) + جاذبية
  السعر مقابل الوسيط + الثقة (عدد وجودة المقارنات) + جودة البيانات، مع خصم الناقص
  والبعيد عن المنطقة.
- **ترتيب المصداقية**: الصفقات الرسمية > الإعلانات (نفس المنطقة/النوع/العملية).
- **التوسعة**: عند ندرة نتائج المنطقة، تُضاف نتائج المحافظة **موسومة بوضوح**
  «خارج المنطقة المطلوبة» وتُحسب منفصلة عن المطابقات.
- **الأدلة**: كل مقارنة/دليل يحمل اسم المصدر + تفاصيل الإعلان + زر «فتح الإعلان
  الأصلي ↗» (الرابط الأصلي) — وكل مصدر يعلن آلية جلبه ونقطة نهايته.
- **المساحة**: لا تُحسب أرقام الارتداد/الواجهة كمساحة — فقط المساحة الفعلية المذكورة.

## 12) ملخص الميزات الحديثة (حتى لا يعيد وكيل جديد بنائها)

- التوفيق بين العرض والطلب (تبويب «العرض والطلب» في أفضل الفرص هو الموطن الوحيد للبيانات؛ لوحة السوق تعرض ملخصًا فقط بزر تنقّل ذكي).
- «الأفضل» الافتراضي بشارات الفئة، فلتر مباشر/مكتب بعدّادات، «الجديد والمحذوف» بإرشادات.
- حصاد السوق → `market_listings` (قاعدة المعرفة المتراكمة) + جدول 010 + وثيقة SUPABASE_SETUP.
- عدّادات داخل أزرار التبويبات، شريط تبويبات رئيسي، شبكة أزرار متساوية على الجوال.
- فحوص الجوال الآلية (تجاوز + لمس) في أمر واحد وCI.
- وكيل إكمال التفاصيل: يقرأ صفحة تفاصيل كل إعلان ناقص (سعر/مساحة/منطقة/محافظة/هاتف) ويكمّلها
  قبل الفلترة والتقييم — في مسارَي البحث والحصاد، بحالة ظاهرة في تبويب المصادر.
- زر «تواصل مع المعلن (واتساب)» في بطاقات الفرص والنتائج عند توفر هاتف المعلن (من Q8Aqar/
  Mourjan/4Sale/بوعقار) — برسالة جاهزة بملخص الفرصة وأدلتها، ويُحسب عدد الهواتف لكل موقع
  في جدول تحليلات الحصاد.
- وكيل اكتشاف التطورات (تبويب 📰): أخبار ومؤشرات عقارية كويتية من مصادر متخصصة
  (KFH/وزارة العدل/صحافة) بفلترة دقيقة (كلمات عربية + إنجليزية بحدود كلمة + سياق
  كويتي) + فحص منصات مرشحة — يحفظ في القاعدة والملف المحلي ويعرضها المنصة.
- كل الأرقام المعروضة بالإنجليزية (0-9): تحويل العربية الهندية (٠-٩) وفواصلها عند
  دخول النص (الموصلات + ملف الفريج) وعند العرض (الواجهة وPDF) — لا أرقام عربية في الواجهة.
- تحليلات السوق بمعايير جودة: تنظيف شواذ 3×IQR + سقف واقعي للعائد (≤15%) + حارس موثوقية
  (عينتان على الأقل لكل جانب + شرط سعر > الإيجار السنوي) مع شارة «ثقة عالية/تقديري»،
  واتجاه سوق عام (صاعد/مستقر/هابط) — والرسم الزمني يدرج النقاط الصالحة فقط (شهر بلا
  سعر متر لا يُرسم كصفر).
- شفافية المصادر: `SOURCE_MECHANISMS` + `fetchMethod`/`endpoint` في كل حالة مصدر.
- سهولة الوصول للمصادر: شريط «مصادر هذه النتائج» فوق النتائج المرتبة — كل منصة
  ساهمت بعدّاد إعلاناتها ورابط مباشر للموقع المفحوص (الوكلاء الداخليون `kind: internal`
  لا يظهرون فيه)، وأزرار الفتح في كل البطاقات باسم المصدر («فتح على Mourjan»…).
  كل شريحة تحمل **مؤشر جودة**: نقطة ملونة بدرجة ثقة المصدر (`trust.score` أخضر قوي /
  كهرماني متوسط / أحمر ضعيف) وتلميح «ثقة المصدر: X%» عند التمرير — ونفس المؤشر في
  شريط مصادر الفرص بمتوسط ثقة الفرص لكل منصة. الشريط يضم زر **«نسخ روابط المصادر»**
  ينسخ قائمة المنصات وروابطها المفحوصة وعدد إعلاناتها وثقتها جاهزة للمشاركة.
  نفس الشريط يظهر فوق بطاقات أفضل الفرص (تبويبات الأفضل/اليومية/الأسبوعية/الشهرية/السنوية)
  مع **فلترة حية بالنقر على أي منصة** (`oppState.platform` + شريط `oppSourcesBar`).
- الوضع الثابت: بديل تحليل داخل المتصفح + تراجع تلقائي + PDF مطبوع.
- logging منظم بمستوى `ALFORAIJ_LOG_LEVEL` لكل تشغيل مصدر (نجاح/فشل/سبب/مدة/محاولات).
- إصلاح 4Sale: إعادة محاولة بخطأ مؤقت مع مصدر بديل.
- تقرير PDF عربي احترافي (شعار/مقارنات/تقييم/تمويل/توصيات) عبر reportlab.
