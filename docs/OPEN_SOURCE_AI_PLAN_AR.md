> إجابة مفصلة عن: كيف ينفعنا الذكاء الاصطناعي مفتوح المصدر (Llama من Meta، Nemotron وTensorRT من Nvidia) مجانًا؟
> هذه وثيقة **تنفيذ** بمراحل مرتبة بالأثر، مع تكلفة $0 حيث أمكن، وتحذيرات صادقة.
> المرتبط: [نظرة المشروع](PROJECT_OVERVIEW_AR.md) · [مصادر البيانات](DATA_SOURCES.md)

## 1) الخلاصة التنفيذية

أكبر قيمة للذكاء الاصطناعي في منصتنا **ليست** في كتابة التقارير العربية (قوالبنا جاهزة وUTILITY معتمدة) — بل في **تنظيف وبنية بيانات الإعلانات** (استخراج المنطقة والنوع والسعر والمساحة من نص عربي فوضوي). كلما كانت بياناتنا أنظف، كان تقييمنا أدق، وهذا هو وعدنا: «مجاني وأدق». النماذج مفتوحة المصدر تنجز ذلك **بلا رسوم لكل طلب** و**بلا تسريب بيانات المستخدم لطرف خارجي** — ميزة تنافسية وخصوصية معًا.

| المهمة | النموذج المفتوح | التكلفة |
|---|---|---|
| استخراج حقول من نص الإعلان | Llama 3.1/3.3 8B أو Qwen2.5 7B (أفضل عربيًا) | $0 (Ollama على CPU) |
| تصنيف نوع العقار/المنطقة | نموذج صغير مخصص (LoRA على 8B) | $0 بعد التدريب |
| كتابة خلاصة التقييم (تقرير PDF) | Llama 3.1 8B محليًا | $0 |
| الترجمة/التطبيع (نصوص إنجليزية-عربية) | NLLB / SeamlessM4T (Meta) | $0 |
| تسريع الاستدلال عند الحاجة لـGPU | TensorRT-LLM / vLLM (Nvidia) | $0 برمجيًا (يحتاج GPU) |
| تحليل بيانات الأسعار على GPU | RAPIDS (Nvidia) | $0 برمجيًا |

## 2) أين تلمس المنصة فعلًا (مرتبة بالأثر)

### 2.1 بنية نص الإعلان → بيانات منظمة (الأثر الأعلى)
الإعلانات تصل نصًا حرًا: «بيت دورين جديد في صباح السالم قريب دوار، ٤٢٠م، دور ٤ غرف وصالة…». اليوم الاستخراج قواعدي جزئيًا. نموذج Llama محلي يستخرج JSON منضبطًا:
```json
{ "area": "صباح السالم", "type": "بيت", "price_kwd": 180000,
  "size_m2": 420, "floors": 2, "bedrooms": 4, "condition": "جديد" }
```
**بوابة دقة إلزامية**: الناتج لا يدخل القاعدة إلا إذا اجتاز تحققًا قواعديًا (المنطقة في `kuwait_areas.json`، السعر ضمن نطاق منطقي للمنطقة/النوع، الحقول رقمية). أي شك → يُهمَل الحقل ولا يُحتسب — نفس فلسفة «لا رقم بلا مصدر».

### 2.2 تغذية التقييم والفرص
الحقول المستخرجة تنظّف `market_listings` (تطبيع المنطقة والعنوان) فتتحسن: التقييم بالصفقات المشابهة، درجة الفرصة، سجل السعر، ونقاط الخريطة — كلها تعتمد على جودة هذا الحقل.

### 2.3 كشف «شبه التكرار» الذكي
مطابقة الإعلان المكرر عبر مصادر مختلفة بمعنى النص (نفس «بيت دورين جديد قرب دوار») — أذكى من القواعد، مع نفس بوابة الدقة القائمة (منطقة+نوع+سعر+تطبيع عنوان) لمنع دمج وحدات متشابهة شرعيًا.

### 2.4 خلاصة التقييم في بطاقة المشاركة والتقرير
توليد 3-5 أسطر خلاصة عربية لكل تقييم (بدل النص الجامد) — يزيد جاذبية بطاقة واتساب. القيود: **قالب واتساب UTILITY ثابت لا يتغير** — الخلاصة حقل متغير داخل القالب، والتوليد محلي فخصوصية كاملة.

### 2.5 التحليل التنبؤي (المرحلة المتقدمة)
تدريب نموذج صغير (LightGBM أو نموذج شبكي) على `official_transactions` + `price_trends` للتنبؤ باتجاه المناطق خلال 12–24 شهرًا — **التنبؤ بالأرقام يبقى إحصائيًا حتميًا لا LLM** (النماذج اللغوية تهلوس بالأرقام). LLM يكتب التقرير التفسيري فقط.

## 3) خطة التنفيذ بمراحل (بتكلفة $0 أولًا)

### المرحلة 0 — تجربة بلا بنية تحتية (أسبوع)
- جرّب النماذج مجانًا قبل الالتزام بأي خادم:
  - **OpenRouter** (مجموعة Free Models) أو **NVIDIA Build/NIM catalog** (رصيد تجريبي مجاني).
  - **Ollama محليًا** على جهاز التطوير: `ollama run llama3.1:8b` / `qwen2.5:7b` — جرّب الاستخراج على 100 إعلان فعلي من قاعدة البيانات وقِس دقة الحقول يدويًا.
- **قرار البوابة**: إن تجاوزت الدقة 90% على الحقول الحرجة (منطقة/سعر/مساحة) → ننتقل للمرحلة 1.

### المرحلة 1 — استخراج منظم في خط الحصاد (شهر)
- خدمة Python صغيرة (`services/llm_extract.py`) تتصل بـ Ollama على **VPS رخيص CPU فقط** (~$20-40/شهر) مع نموذج 8B مكمّم (Q4) — يعمل على CPU ببطء مقبول (إعلان/ثانية تقريبًا).
- تُشغَّل **خارج المسار الحرج**: الوكيل اليومي يحصد ويحفظ أولًا، ثم تملأ خطوة معالجة ثانوية الحقول المستخرجة — لا يؤثر فشلها على الحصاد (نمط بوابة الجاهزية القائم).
- بوابة دقة + سجل نتائج (`extraction_runs`) لقياس الجودة أسبوعيًا.

### المرحلة 2 — تخصيص وتقليص التكلفة (2-3 أشهر)
- استخدم مخرجات المرحلة 1 (المحققة يدويًا) **بيانات تركيبية لتدريب مصنّف صغير** (LoRA على 8B أو نموذج تصنيف تقليدي) لتصنيف النوع/المنطقة — أسرع وأرخص من LLM عام لكل إعلان.
- الأوزان تبقى مفتوحة ومجانية (رخصة Llama التجارية مسموحة؛ Qwen رخصة Apache 2.0).

### المرحلة 3 — AVM بالاختبار الرجعي (3-6 أشهر)
- نموذج تسعير على `official_transactions` (سعر لكل م2 حسب المنطقة/النوع/القدم) **باختبار رجعي شهري منشور**: «خطأ النموذج في توقع صفقات الشهر الماضي: X%».
- LLM يكتب التقرير التفسيري فقط — الأرقام من النموذج الإحصائي حصرًا.

### المرحلة 4 — تسريع الاستدلال (عند الحاجة فقط)
- إن نما الحجم وتوفر GPU: **vLLM** أو **TensorRT-LLM** مع **Triton Inference Server** (كلها مفتوحة من Nvidia) لرفع الإنتاجية — **لا حاجة لها في البداية**، ولا تشترِ GPU قبل إثبات الطلب.

## 5) تحذيرات صادقة (لا تتجاهلها)

1. **لا تستخدم LLM لأرقام التقييم** — يهلوس بالأرقام. الأرقام من الصفقات المسجلة والإحصاء، وLLM للاستخراج والكتابة فقط.
2. **جودة العربية**: Llama 3.1/3.3 جيد، لكن **Qwen2.5 غالبًا أدق عربيًا** — قِس على عيّنتك قبل الاختيار. (نماذج عربية مفتوحة مثل Jais خيار إضافي.)
3. **البنية التحتية**: تشغيل 8B محليًا يحتاج VPS (تكلفة شهرية ثابتة) أو جهاز مطور — «مجاني» يعني بلا رسوم ترخيص/لكل طلب، لا بلا أجهزة.
4. **قوالب واتساب**: المعتمدة UTILITY ثابتة — الذكاء الاصطناعي يملأ الحقول المتغيرة فقط، لا يغيّر القالب.
5. **خصوصية البيانات**: الاستدلال المحلي يبقي بيانات الإعلانات والمستخدمين داخل خادمنا — ميزة تُسوَّق، والتزام يُحترم.
6. **الرخص**: Llama (رخصة مجتمع Meta — تجارية مسموحة)، Qwen/Nemotron (Apache/مفتوحة) — وثّق النموذج المستخدم في كل تقرير (شفافية).
