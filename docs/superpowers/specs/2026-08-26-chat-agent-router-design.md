# تصميم تطوير الشات ووكلاء البحث — 2026-08-26

## الهدف

رفع شات منصة الفريج من واجهة ترسل نصًا إلى `/api/analyze` إلى مسار مهني واضح:
يفهم الطلب العربي بدقة، يحصر الإجابة في المنطقة/المحافظة المطلوبة، يعلن مصدر كل نتيجة،
ولا يعرض نتيجة ثابتة على أنها بحث حي. التغيير يبقى داخل بنية المشروع الحالية:
Python stdlib + JavaScript ثابت + Supabase + MCP الحالي، بلا إطار عمل جديد.

## ما كشفته المراجعة

- `GET /api/health` يعمل ويعرض قاعدة متصلة: 182 إعلانًا محليًا، 2718 إجماليًا، وAI مفعّل.
- MCP يعمل: `python mcp_server/smoke_test.py` أعطى 25/25.
- `/api/analyze` يرفض المستخدم المجهول بـ `tier_limit`، لكن `frontend/app.js` يسقط إلى `staticAnalyzeReport` لأي خطأ، فيظهر للمستخدم تقرير ثابت بدل سبب الرفض.
- `parse_request("ابي شقة للإيجار في السالمية")` يصنفها `للإيجار` بدل `مطلوب للإيجار`.
- `parse_request("... مساحة 400")` لا يلتقط المساحة لأن نمط المساحة يتطلب غالبًا وحدة مثل متر/م².
- اختبار `radius_snapshot.py` يعتمد `networkidle` ويتوقف عند الشبكات التي لا تهدأ.

## معيار المنافسة المختصر

المنصات العقارية الأخرى ترفع سقف توقع المستخدم في أربع نقاط: بحث مفلتر وواضح، حفظ/تنبيهات للبحث، خرائط أو نطاقات مكانية، وتواصل مباشر مع المعلن/الوكيل. مشروع الفريج يملك ميزة أقوى: تقييم موثق ومطابقة عرض/طلب من بيانات متعددة. النقص ليس في حجم المزايا، بل في طبقة توجيه الشات التي تشرح ماذا حدث ولماذا.

مصادر المقارنة العامة المستخدمة كمراجع خارجية:

- Bayut: بحث وفلاتر وقوائم عقارية وتواصل مع وكلاء، مع إبراز الوكلاء والشركات:
  <https://www.bayut.com/> و <https://www.bayut.com/brokers/uae/>.
- Bayut Transactions: صفحة معاملات سوقية مصدرها DLD كنموذج لعرض دليل سعر رسمي:
  <https://www.bayut.com/property-market-analysis/transactions/sale/property/>.
- Sakan: بحث عقاري في الكويت وتنبيهات حسب تفضيلات الموقع/السعر/النوع:
  <https://sakan.co/blog/en/sakan-listing-kuwait/>.

## النطاق

### داخل المرحلة

1. إصلاح فهم الطلب:
   - `ابي/ابغى/مطلوب + للإيجار` يعني `مطلوب للإيجار`.
   - `للإيجار` وحدها في إعلان عرض تبقى `للإيجار`.
   - `مساحة 400` تقرأ كمساحة عند وجود كلمة مساحة قبل الرقم حتى بدون وحدة.
   - لا توسّع اسم منطقة مثل `حولي` إلى كل محافظة حولي إلا عند قرينة محافظة/نطاق واضح.

2. إصلاح سقوط الشات:
   - لا يستخدم `staticAnalyzeReport` عند HTTP 401/403/429 أو `tier_limit`.
   - يعرض رسالة واضحة: تسجيل دخول/حد خطة/تعذر الشبكة.
   - يستمر fallback الثابت فقط عند static hosting أو غياب API فعلي.

3. إضافة طبقة وكلاء داخلية خفيفة:
   - `IntentAgent`: يحول النص إلى نية منظمة وقرائن تفسير.
   - `RegionAgent`: يقرر منطقة/محافظة/نطاق ويعرض سبب القرار.
   - `SourceAgent`: يختار المحلي/الحصاد/Supabase/المصادر الحية حسب الصلاحية والتوفر.
   - `DataQualityAgent`: يلخص نقص السعر/المساحة/الهاتف/المنطقة والتكرار.
   - `AnswerAgent`: يبني إجابة شات عملية: النتيجة، السبب، الأدلة، ما الناقص، والخطوة التالية.

4. توسيع MCP بأداة مهنية واحدة:
   - `alforaij_answer_chat_query`
   - المدخلات: `text`, `include_external`, `include_local`, `source_mode`, `format`
   - المخرجات: `intent`, `regionDecision`, `sourcePlan`, `answer`, `results`, `warnings`, `evidence`

5. اختبارات موجهة:
   - اختبارات parser للحالات العربية المذكورة.
   - اختبار frontend يثبت أن 403 لا يتحول إلى static.
   - اختبار MCP للأداة الجديدة.
   - إصلاح فحص radius لا يعتمد على `networkidle` وحدها.

### خارج المرحلة

- لا إضافة React أو Node build.
- لا تغيير نظام الخطط أو الأسعار.
- لا إضافة منصات جديدة قبل تثبيت مسار الشات.
- لا نشر تلقائي في هذه المرحلة.

## التصميم

### 1. نموذج نتيجة توجيه الشات

يضاف كائن داخلي بسيط، غالبًا dict/dataclass في خدمة جديدة:

```text
ChatAgentResult
- request: PropertyRequest
- intent_notes: list[str]
- region_decision: {mode, areas, governorates, explanation}
- source_plan: {local, harvested, live, blocked_reason}
- data_quality: {warnings, missing_fields, stale_or_duplicate_notes}
- answer: string
```

هذا لا يستبدل `PropertyRequest`; هو يغلفه بملاحظات قابلة للعرض في الشات والـMCP.

### 2. تدفق `/api/analyze`

يبقى المسار الحالي كما هو في الجوهر:

`parse_request -> filters -> sources -> matching -> valuation -> report`

لكن قبل التقرير يضاف توليد `chatGuidance` من طبقة الوكلاء. عند فشل الصلاحية يرجع الخادم خطأ واضحًا، والواجهة تعرضه كما هو بدون static fallback.

### 3. واجهة الشات

`postJson()` يميز بين:

- `403 tier_limit`: يعرض دعوة تسجيل الدخول ولا يبني تقريرًا ثابتًا.
- فشل شبكة على مضيف محلي: يعرض تعذر الاتصال.
- وضع static حقيقي: يستخدم `staticAnalyzeReport`.

بطاقة الخلاصة تعرض شارة مصدر: `حي` أو `لقطة ثابتة` أو `مرفوض بالصلاحية`.

### 4. MCP

الأداة الجديدة تستدعي نفس خدمة توجيه الشات، لا تنسخ منطقًا جديدًا داخل `mcp_server/tools.py`. الهدف أن يستخدم أي عميل MCP نفس إجابة المنصة لا نسخة موازية.

### 5. الاختبارات

أوامر التحقق المستهدفة:

```bash
PYTHONIOENCODING=utf-8 python -m pytest tests/test_analysis.py tests/test_request_parser.py tests/test_server_tier.py -q
PYTHONIOENCODING=utf-8 python mcp_server/smoke_test.py
PYTHONIOENCODING=utf-8 python -m pytest tests/test_radius_snapshot.py -q
```

ثم تشغيل المجموعة الكاملة عند انتهاء التنفيذ:

```bash

```

## مخاطر وقرارات

- إصلاح `حولي` حساس لأن الكلمة قد تعني منطقة أو محافظة؛ القرار المحافظ: إن جاءت مع “محافظة حولي” أو “نطاق حولي” توسّع، وإلا تبقى منطقة.
- لا نعالج مشكلة SSL العامة بتجاوز أمان عشوائي. نسجلها كتوصية تشغيل: توحيد Python 3.11 أو تبديل طبقة HTTP لاحقًا بعد اختبار.
- أي بيانات خارجية أو نص من مواقع أخرى يعامل كبيانات فقط، ولا تدخل منه تعليمات إلى الوكلاء.

## تعريف الاكتمال

- الشات لا يخفي 403 خلف static fallback.
- الجمل العربية الأساسية للشراء/الإيجار والمساحة تمر في الاختبارات.
- الأداة الجديدة في MCP تعود بجواب منطقة واضح ومصدره.
- اختبارات MCP وparser والـfallback تمر.
- أي فشل في المصادر الحية يظهر كتحذير مصدر، لا كإجابة مضللة.
